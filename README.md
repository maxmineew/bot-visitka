# Бот-визитка

Telegram-бот-визитка для демонстрации кейсов (AI-боты, no-code автоматизации, веб-разработка) с прямыми ссылками на связь и заказ разработки.

Стек: Python 3.11+, [aiogram 3](https://docs.aiogram.dev/), long polling.

## Структура

```
main.py              # точка входа: Bot, Dispatcher, polling
config.py            # чтение переменных окружения
content/cases.yaml       # содержимое кейсов
content/loader.py         # загрузка и выборка кейсов из YAML
keyboards/            # inline-клавиатуры
handlers/              # обработчики команд и callback-кнопок
texts/messages.py       # статические тексты бота
assets/cases/<id>/      # скриншоты кейсов
deploy/bot-visitka.service  # systemd unit для деплоя на сервер
```

## Запуск локально

1. Получите токен бота у [@BotFather](https://t.me/BotFather).
2. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` (остальные переменные — контакты — уже заполнены значениями по умолчанию, при необходимости поменяйте).
3. Установите зависимости:

   ```bash
   python -m venv .venv
   source .venv/Scripts/activate   # Windows Git Bash
   pip install -r requirements.txt
   ```

4. Запустите бота:

   ```bash
   python main.py
   ```

5. В Telegram отправьте боту `/start`.

## Редактирование кейсов

Все кейсы хранятся в `content/cases.yaml`. Каждый кейс — это:

- `featured: true` — попадает в основной список кейсов (полная карточка);
- `featured: false` — попадает в список «Ещё кейсы» (краткая строка без карточки).

Поля карточки: `title`, `client`, `product`, `tasks` (список), `result`, опционально `review` и `detailed_case` (текст, показывается по отдельным кнопкам), `images` (список имён файлов из `assets/cases/<id>/`), `links` (доп. кнопки-ссылки, например на живой сайт проекта).

Чтобы добавить скриншот к кейсу — положите файл в `assets/cases/<id>/` и укажите его имя в `images`.

## Демо-сценарии

Пункт меню «🎮 Живые демо» (`handlers/demo.py`, `texts/demo.py`, `keyboards/demo.py`)
даёт посетителю самому пройти 4 коротких интерактивных сценария вместо чтения
текста о кейсе: психолог (запись на консультацию через пару вопросов),
нутрициолог (квиз на 3 вопроса → тип питания), нумеролог (дата рождения → число
жизненного пути) и AI-агент (живой диалог без кнопок на примере школы
программирования CodeStart).

Все 4 сценария работают на FSM (`aiogram.fsm`, `MemoryStorage`, состояния — в
`handlers/demo_states.py`). Важно: демо AI-агента **не обращается к какому-либо
LLM** — это сознательно скриптованный диалог на счётчике шагов (ответ
пользователя не анализируется), чтобы демонстрировать механику без API-ключей и
затрат на токены. Об этом честно сказано и в финальном сообщении сценария.

Персонажи (Игорь Реутов, Светлана Орлова, Тимофей Волков, школа CodeStart) —
вымышленные, придуманы для этого проекта.

## Учёт визитов

Бот ведёт локальный лог обращений в `analytics/visits.db` (SQLite) и раз в
~15 секунд после последнего действия пересобирает Excel-отчёт и выгружает
его на Яндекс.Диск (если задан `YANDEX_DISK_TOKEN`).

**Что сохраняется (и что — нет).** Чтобы не собирать персональные данные
(152-ФЗ), в отчёт попадают только:

- `telegram_id` — числовой ID Telegram-аккаунта (не username, не имя, не телефон);
- время первого и последнего визита, количество визитов (новый визит = обращение после паузы 30+ минут);
- какие кнопки/разделы бота нажимали (`callback_data`) или имя команды (`/start`) — без произвольного текста, который мог бы ввести пользователь.

Username, имя, фамилия, телефон и текст сообщений НЕ сохраняются нигде.
Чтобы связаться с посетителем по `telegram_id`, точной ссылки без username
Telegram не даёт — этот ID полезен, чтобы отличать повторных посетителей
друг от друга и видеть их путь по кейсам, а не для прямого выхода на связь.

**Настройка выгрузки на Яндекс.Диск:**

1. Откройте https://yandex.ru/dev/disk/poligon/ и нажмите «Получить OAuth-токен» (нужен доступ на чтение и запись в Диск) под своим Яндекс-аккаунтом.
2. Впишите токен в `.env` как `YANDEX_DISK_TOKEN`.
3. При необходимости поменяйте `YANDEX_DISK_PATH` (путь и имя файла на Диске, по умолчанию `/Бот-визитка/visits.xlsx`).
4. Если `YANDEX_DISK_TOKEN` не задан — отчёт продолжает собираться локально, просто без выгрузки.

Файл на Диске перезаписывается целиком при каждой выгрузке — открывайте его позже через Диск заново, а не держите постоянно открытым в редакторе.

## Деплой на Beget (VPS/облачный сервер, systemd)

Бот работает через long polling — входящие порты открывать не нужно, домен и
SSL тоже не требуются. Достаточно VPS/облачного сервера Beget с root/SSH-доступом
(Ubuntu/Debian) и исходящим доступом в интернет (к api.telegram.org и
cloud-api.yandex.net), который включён по умолчанию.

### 1. Первый деплой

1. Узнайте в панели Beget IP-адрес сервера и данные для SSH (обычно `root@<IP>`).

2. Загрузите код проекта на сервер (выполняется на вашем компьютере, в Git Bash,
   из папки проекта). Команда упаковывает проект в архив и сразу распаковывает
   его на сервере в `/opt/bot-visitka`, исключая venv/кэш/локальную БД визитов:

   ```bash
   tar czf - \
     --exclude=.venv --exclude=__pycache__ --exclude=analytics/visits.db* \
     --exclude=logfile --exclude=.env \
     . | ssh root@<IP> "mkdir -p /opt/bot-visitka && tar xzf - -C /opt/bot-visitka"
   ```

3. `.env` содержит секреты (токен бота, токен Яндекс.Диска) и намеренно исключён
   из архива — загрузите его отдельно, один раз (и повторно, только если меняли
   значения в нём):

   ```bash
   scp .env root@<IP>:/opt/bot-visitka/.env
   ```

4. Зайдите на сервер по SSH и запустите скрипт настройки — он поставит Python,
   создаст отдельного системного пользователя `bot-visitka`, виртуальное окружение,
   установит зависимости и запустит бота как systemd-сервис:

   ```bash
   ssh root@<IP>
   cd /opt/bot-visitka
   sudo bash deploy/setup_server.sh
   ```

5. Проверьте статус и логи:

   ```bash
   sudo systemctl status bot-visitka
   journalctl -u bot-visitka -f
   ```

   В логе должна появиться строка `Run polling for bot @signea_cases_bot...` —
   значит бот на сервере подключился к Telegram. После этого можно останавливать
   локальный запуск на своём компьютере (два процесса с одним и тем же токеном
   на polling конфликтуют — Telegram вернёт ошибку `Conflict`, если оба будут
   активны одновременно).

### 2. Обновление кода после изменений

Повторите шаги 2 и 4 (загрузка архива + `sudo bash deploy/setup_server.sh`) —
скрипт идемпотентен, он переустановит зависимости при необходимости и
перезапустит сервис. `.env` и `analytics/visits.db` при этом на сервере не
затрагиваются (они не входят в архив).

Если менялся только код (без `requirements.txt`), можно просто перезапустить
сервис без повторного запуска setup_server.sh:

```bash
ssh root@<IP> "sudo systemctl restart bot-visitka"
```
